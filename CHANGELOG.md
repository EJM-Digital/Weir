# Changelog

One line per released version, newest first. Each line links the full release notes in
[`docs/release-notes/`](docs/release-notes/) and the GitHub release with its downloads.

Versions follow `MAJOR.MINOR.PATCH`, with `-rc.N` for release candidates. A major version can contain
breaking changes, which its notes list first.

Earlier version numbers were retired when Weir restarted at 1.0.0-rc.1. Their history stays in git.

## 1.x

- **1.0.0-rc.21** (2026-10-28). Signing out now ends the session even if you close the page at once, a call to a media manager is no longer lost on a connection the manager had already closed, a library clean with an unreadable file check is refused with a reason, and Weir's server code and tooling are now tested to 100% of lines and branches. [notes](docs/release-notes/v1.0.0-rc.21.md) · [release](https://github.com/EJM-Digital/Weir/releases/tag/v1.0.0-rc.21)
- **1.0.0-rc.20** (2026-10-22). Two update fixes and a round of plain-words and small fixes from wider testing: About shows the answer of a manual update check while automatic checking is off, a busy computer no longer makes an update give up on its safety copy, confirmation and Activity messages are in plain words, and detection windows, restored times and library cleans no longer go wrong. [notes](docs/release-notes/v1.0.0-rc.20.md) · [release](https://github.com/EJM-Digital/Weir/releases/tag/v1.0.0-rc.20)
- **1.0.0-rc.19** (2026-10-20). Weir now lives at github.com/EJM-Digital/Weir and its container image moves to `ghcr.io/ejm-digital/weir` (the old `ghcr.io/jampat000/weir` is no longer updated, so Docker users change `image:` and pull again; nothing changes for the Windows installer). A long test-and-fix sweep of every screen, setting and hand-off: only an administrator can remove a connection or an alert, a report Deluno could not take yet is sent again, a reject asks a busy manager again, a paused Weir changes no file, alerts hide their address and say the right thing, rule sets do what they say, settings keep what you typed, and the search lanes, home note and separate Movies and TV hours window that did nothing are gone. [notes](docs/release-notes/v1.0.0-rc.19.md) · [release](https://github.com/EJM-Digital/Weir/releases/tag/v1.0.0-rc.19)
- **1.0.0-rc.18** (2026-10-14). The first Windows release since rc.13, and everything user-facing from rc.17, whose Windows release page went up with no files: the release is now made as a draft, every file is attached and checked, and only then is it published; a busy database answers 503 with Retry-After and the code database_busy, an unforeseen failure answers JSON with the code internal_error, and the new setting WEIR_SQLITE_BUSY_TIMEOUT_SECONDS sets how long a write waits; Weir no longer stalls on requests on a busy or small machine, a Windows update can no longer leave Weir not running, a start that goes wrong is watched and tried again, downloads sent twice get the right answer, and every release is proven on a clean machine before it is tagged. [notes](docs/release-notes/v1.0.0-rc.18.md) · [release](https://github.com/jampat000/Weir/releases/tag/v1.0.0-rc.18)
- **1.0.0-rc.17** (2026-10-14). Docker only; its Windows files did not publish (immutable release), so Windows users get its changes in rc.18. On a busy or small machine Weir no longer stalls on requests while it looks again at a file that is not there, a new log warning records any wait for a thread, the tray counts its server ready only when that same server says it is, the contract suite and CI keep better evidence of a failure, and everything from rc.14, rc.15 and rc.16 is here: a Windows update can no longer leave Weir not running, a start that goes wrong is watched and tried again with plain notices and a new server-host.log, downloads sent twice get the right answer, a file that comes back is picked up, imported films stay imported, Weir's icon gets an inset border like Deluno's, and every release is proven on a clean machine before it is tagged. [notes](docs/release-notes/v1.0.0-rc.17.md) · [release](https://github.com/jampat000/Weir/releases/tag/v1.0.0-rc.17)
- **1.0.0-rc.16** (2026-10-13). Never published: its scenario run on a clean machine found that, on a busy machine, Weir stalled on requests for up to 84 seconds, because rc.16 looked again at files that were not there and held request threads while it did; everything in it ships in 1.0.0-rc.17 for Docker and 1.0.0-rc.18 for Windows, with the cause fixed. [notes](docs/release-notes/v1.0.0-rc.16.md)
- **1.0.0-rc.15** (2026-10-12). Never published: its scenario run on a clean machine found that updating from rc.13 could leave Weir not running, and everything in it ships in 1.0.0-rc.17 for Docker and 1.0.0-rc.18 for Windows, by way of rc.16. [notes](docs/release-notes/v1.0.0-rc.15.md)
- **1.0.0-rc.14** (2026-10-11). Never published: its scenario run on a clean machine found problems in the run itself, and everything in it ships in 1.0.0-rc.17 for Docker and 1.0.0-rc.18 for Windows, by way of rc.15 and rc.16. [notes](docs/release-notes/v1.0.0-rc.14.md)
- **1.0.0-rc.13** (2026-10-10). Check, download and apply an update from System › About without waiting for the tray, a checked copy of your data before every update, a frozen ffmpeg stopped after 10 minutes without progress, and files under a workflow's minimum size left out of a hand-off. [notes](docs/release-notes/v1.0.0-rc.13.md) · [release](https://github.com/jampat000/Weir/releases/tag/v1.0.0-rc.13)
- **1.0.0-rc.12** (2026-10-09). The tray's dot shows Weir's health only, an extra skipped for being too small no longer needs you, files that leave early settle at once, and the first-run port window opens in front. [notes](docs/release-notes/v1.0.0-rc.12.md) · [release](https://github.com/jampat000/Weir/releases/tag/v1.0.0-rc.12)

[notes](docs/release-notes/v1.0.0-rc.11.md) · [release](https://github.com/jampat000/Weir/releases/tag/v1.0.0-rc.11)

# Weir v1.0.0-rc.19

Date: 2026-10-20

> **Early days.** Weir is early, and it is in active, hard testing. Expect rough edges. If something is wrong or confusing, please report it on [GitHub issues](https://github.com/EJM-Digital/Weir/issues).

Weir's container image has a new home: `ghcr.io/ejm-digital/weir`. From this release on, the old name, `ghcr.io/jampat000/weir`, is no longer updated. If you run Weir with Docker, change `image:` in your compose file (or your `docker run` command) to the new name, then run `docker compose pull` and `docker compose up -d`. Your settings and data are not touched. Nothing changes for the Windows installer.

The project now lives at [github.com/EJM-Digital/Weir](https://github.com/EJM-Digital/Weir), and the documentation is at [ejm-digital.github.io/Weir](https://ejm-digital.github.io/Weir/).

This release is the result of a long test-and-fix sweep: every screen, setting and hand-off was checked in a real browser, against real recorded replies from Deluno, Sonarr, Radarr and your download clients, and on real files with the real tools. That found a good many wrong results, and all of them are fixed here. Nothing in this release needs anything from you except the Docker image name above.

## New

- **Weir's windows and lists update by themselves in more places.** The list of signed-in browsers on the Security tab changes as soon as another browser signs in or out, and a change to Playback devices made in one browser shows in every other open browser without a reload.
- **A backup made by hand counts as the last backup.** **Last backup** on System now shows a backup made with **Back up now**, and says it was made by hand. The schedule stays where it was.
- **Clear wording when a start cannot take its port.** If another program already holds Weir's port, Weir now says which port is in use and the tray tries again like any other failed start. On Windows nothing else can take a port beside a running Weir any more.
- **A notice for a viewer who signs in before setup is finished.** A viewer who signs in before the first-run wizard is done now sees a plain note that an administrator needs to finish setting Weir up. They are not sent to the wizard or offered Skip.
- **A busy database is explained in its own words.** When the database is busy, every screen now shows the sentence Weir gives (what happened and how long to wait) instead of a general "something went wrong".
- **Removed settings that did nothing.** The search lanes, the "home note" shown after sign-in and the separate Movies and TV hours window never changed anything, so they are gone. Searching stays with your media manager and the weekly schedule is the one place for hours. A database from rc.18 upgrades on its own, and an older client or a restored backup that still sends them is not refused.

## Fixed

Who may do what:

- **Only an administrator can remove a connection or an alert.** Removing is at least as serious as adding, but an operator could remove a media manager connection, unlink its workflows, give up the reports it owed and remove an alert. Now all four need an administrator. On the Connections screens, Add, Edit, the on/off switch, Remove and replacing a secret are greyed out for operators and viewers with a short note saying why. Testing a connection and sending a test alert stay open to operators.
- **A person who may not use a route learns nothing about it.** Thirty-four write routes answered "422 invalid" to someone not signed in, or a viewer, when the request body was incomplete. They now check who is asking first.
- **A connection that workflows still come from is not removed.** Removing it used to turn those workflows into ones Weir feeds itself, so Weir would scan their folder and might remove originals a download client was still seeding. Weir now refuses, names the workflows, and asks you to unlink them first.

Files and hand-offs:

- **A busy Deluno no longer loses a report.** A hand-off report that Deluno answered with "not yet" (a 503, 408, 429 or any 5xx) was forgotten. It is now kept, sent again after a minute, then after longer waits up to an hour, and given up after a week. A refusal that cannot be fixed by waiting is still not sent again, and Activity says so.
- **A rejection is reported once.** When a download was rejected and the manager had already accepted the report, running the job again reported it a second time.
- **A reject asks a busy manager again.** A release known to be bad was handed back as good if the manager did not answer once. Weir now asks again, like other short failures, and hands the file back only when the tries run out.
- **A file that is back is cleaned at once.** Resuming processing, in the app or from the tray, now wakes the idle workers straight away, and so does a held file that has come back.
- **A paused Weir changes no file.** A paused Weir could still delete a failed download from Activity's Remove dialog and ask a manager to delete a library file for **Download again**. Both are refused, with the reason, while Weir is paused. Every other way a file can change is now listed and checked against the pause.
- **A file's log belongs to its workflow.** Two workflows holding the same path showed each other's log entries, and **Move to top** could raise the wrong workflow's waiting pass. Both now go by workflow and path.
- **A cleaned file reads as clean without a rescan.** After Weir cleaned a library file, the Library table could go back to "Needs cleaning" until the next scan. A clean that changed a file now asks for a fresh scan.
- **A failed publish says what happened in plain words.** A failed publish of a cleaned file, an unchanged copy or a file handed back showed the computer's own words and folder paths in Activity, and a failed hand-back copy was not recorded as one. A workflow that allows one attempt no longer reads "1 times".
- **Folders Weir makes get the ownership you set on Docker.** The folder Weir publishes into and the folders above it now follow `WEIR_DIR_MODE_OUTPUT` and `WEIR_CHOWN_OUTPUT`.
- **A start-up sweep keeps a kept original that did not match.** If a kept original did not match its backup, the next start deleted the backup. It is now left for you, as recorded.
- **A scan of a library folder follows the workflow's own settings.** A workflow with no file types picked took every file, downloader folders were matched by file name only, and hidden folders were not skipped. It now uses the built-in video types, the downloader folder names and hidden folders, as a watched-folder scan does.
- **Sonarr and Radarr answer the scan.** Weir sent a download client's id as a number, which Sonarr and Radarr refuse with an error, and asked Sonarr for episode files without a series. Both are corrected against real recordings of Sonarr and Radarr.
- **A log download for a film with accents in its name works.** A title such as Amelie with an accent used to answer an error. A log that is cut short now says "Showing the newest 500 of 1,234 entries" instead of "Records retained: 500".
- **A tool asked to run at normal priority gets it.** Weir skipped setting the priority for Normal, so a tool could inherit a lower one from Weir.
- **The hardware check no longer says Weir cannot ask FFmpeg when the machine is only busy.** The check now runs at normal priority with a time limit set from measurements, and a real timeout says so in plain words.
- **A tool's time limit counts only the time Weir could run.** A computer that sleeps or is frozen no longer uses up a tool's time.
- **Waking from sleep is not a warning.** A scan that comes late because the computer was asleep, or a job whose lease ran out while it slept, is now information in the log. Only falling behind while Weir ran is a warning.

Alerts and rules:

- **An alert's address never leaves the server whole.** The alerts list and the Edit alert form show the address with its secret part hidden. Leaving it alone keeps the saved address, and **Replace the address** sets a new one. Two alerts can no longer send to the same address.
- **Alerts say the right thing.** A file that failed for good sent "A file finished" and never "A file failed for good", and a test to a destination that answered with an error said it worked.
- **Rule sets do what they say.** The subtitle order was saved and never used, "mark as default: third choice" acted as the first, and "other metadata" alone made every file fail its checks.

Screens:

- **Settings keep what you typed.** The days a cleaned copy waits no longer snap back to the saved value after a failed save. An hours week that you draw and undo no longer counts as unsaved. Leaving Speed, Alerts, Cleanup or the System time zone with unsaved edits now asks first.
- **System, restored and live.** Restoring a backup now restores the backup time of day. Logs no longer call themselves live while the live link is down. A number typed in Log settings is no longer replaced by the saved one when you enter the field again. A cancelled job stops saying Queued. A busy database no longer blanks the machine name and version in the header.
- **Time zone.** The picker offers UTC and keeps any saved time zone it does not list, instead of replacing it with UTC.
- **Dashboard.** A saving under a megabyte reads in KB on **Just finished**, and the Needs you panel says what **Process all again** did.
- **Setup and sign-in.** A refusal from the server is forgotten once you edit the field. Skipping the reopened wizard leaves a finished setup finished. After a password change you land on the sign-in page and it tells you the password was changed.
- **Workflows.** Six small faults in the editor: the switch ignoring the side already chosen, the editor not following the server, the default profile not being choosable again, the folder chain not rechecked after Save, a "Removing" label while a secret was being replaced, and a wrong message when only the daily clean step failed.
- **Dialogs.** While a dialog is open, everything behind it is out of reach of the mouse and keyboard, and focus returns to where you were when it closes.
- **Security.** Each Sign out button stays reachable when the list of browsers is wide.
- **Playback devices.** Unsaved ticks are guarded.

## Under The Hood

- **Tests.** The test suite grew very large and now measures its own coverage in CI, with floors that only go up. It includes real-browser tests for every screen, replies recorded from a real Sonarr, Radarr, the five download clients and Deluno, tests on real media with the real tools, checks of who may call each of the 155 routes, and property-based and fuzz tests. A coverage register in `docs/testing/coverage-register.json` lists what is proved and how.
- **Scenarios in CI.** The clean-machine scenario suite now runs in CI too, in shards: Weir alone, with Deluno and qBittorrent, in a browser, installing and updating on Windows, and the real tray driven through UI Automation. Releases' backups are restored and their databases upgraded from the published images.
- **No more waiting on the clock.** Tests follow signals and fake clocks, not guessed delays. A test that fails now is a bug to find, and CI retries nothing.
- **Releases.** CI fails when Deluno's recordings of Weir are more than one release behind, and a scenario-suite pass carries over to a later commit when nothing that ships changed. Builds and tests run on GitHub's own runners.
- **Docker.** The entrypoint's user mapping, secrets and folder ownership are tested in the image, the arm64 image is started in CI, and the shipped `compose.yaml` is run in CI.
- **The repository owner.** The owner's name is written once per language and checked, and the repository, image and documentation addresses now use EJM-Digital.
- **Shared documents.** `docs/golden-path.md`, `docs/ci-standard.md` and `docs/deluno-weir-contract.md` are updated from Deluno's copies, identical byte for byte.

## Upgrade Notes

- Windows: **Check now** then **Download update** then **Restart and apply** in System › About, or install `Weir-win-Setup.exe` over the top. Before installing, Weir saves a copy of its data. Database updates run on first start.
- Docker: change the image to `ghcr.io/ejm-digital/weir:1.0.0-rc.19` (the old `ghcr.io/jampat000/weir` is no longer updated), then `docker compose pull && docker compose up -d`.
- `WEIR_LIBRARY_SWAP_HOLD_AT` is a test setting. A production install now refuses to start with it set, so remove it if you ever set it.

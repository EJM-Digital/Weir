# Weir v1.0.0-rc.22

Date: 2026-10-30

> **Early days.** Weir is early, and it is in active, hard testing. Expect rough edges. If something is wrong or confusing, please report it on [GitHub issues](https://github.com/EJM-Digital/Weir/issues).

This release adds an optional way to skip sign-in at home, and recovery codes, so a forgotten password is no longer the end of your setup.

## What Changed

- **Skip sign-in for devices on your home network (optional, off by default).** Turn it on in System › Security, or answer the new question in first-run setup. A device that Weir can tell is on your local network is treated as signed in for that one request, with no password and no session left behind. A device on a public address is never skipped. Changing this choice, your password or your username still asks for your current password, even from a device that skipped sign-in.
- **Recovery codes, and "Forgot your username or password?" on the sign-in page.** Setup now shows ten single-use recovery codes once and waits until you have saved them (you can copy them or download them as a text file). System › Security shows how many are left and can make a new set, which voids the old one. On the sign-in page, "Forgot your username or password?" takes a code, shows your username and lets you set a new password. Every recovery signs out every browser, leaves your API keys working, writes an entry to Activity and sends a notification to whoever you have set up to be told.

## Fixes And Stability

- **Docker images always carry Ubuntu's newest security fixes.** A cached build step could keep an older package set after Ubuntu had published a fix (libbrotli, CVE-2026-111497). The image build now notices when Ubuntu's archive changes and installs the update again, and the release builds every image from the same package set that was scanned.
- **The Windows tray records what its icon says.** The tray's log now notes each change of the icon's hover text, such as Starting and Running, which makes a restart easier to follow when diagnosing a problem.
- **A first-time setup of the suite settings no longer fails when two requests arrive together.** Both could try to create the same row, and one failed with a database error. The second now simply uses the first.
- **The rules preview no longer sends the same request twice.** The second request could replace a good result with an error. It now skips a request it has already sent and waits for a changed one until the running preview has finished.
- **The recovery page stays where it is when Weir says you are not signed in.** You are not signed in while you recover, and that answer could send you back to the sign-in page in the middle of using a code. Sign-in, recovery and setup now all stay on their own page.

## Upgrade Notes

- Windows: **Check now** then **Download update** then **Restart and apply** in System › About, or install `Weir-win-Setup.exe` over the top. Before installing, Weir saves a copy of its data.
- Docker: change the image to `ghcr.io/ejm-digital/weir:1.0.0-rc.22`, then `docker compose pull && docker compose up -d`.
- **After updating, Weir asks you to make and save recovery codes.** This happens the first time you sign in, and System › Security keeps reminding you until you have a set. Save them somewhere other than this computer.
- **The `recover` console command is gone.** Recovery codes are now the only way back in. Weir no longer reopens setup when the only account is switched off.
- **If you lose your password and every recovery code, the only way forward is a fresh install with a new data folder.** Nothing else can get you back in, so keep the codes safe.

## Docker

- `ghcr.io/ejm-digital/weir:1.0.0-rc.22`

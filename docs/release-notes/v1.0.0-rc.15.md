# Weir v1.0.0-rc.15

Date: 2026-10-12

> **Early days.** Weir is early, and it is in active, hard testing. Expect rough edges. If something is wrong or confusing, please report it on [GitHub issues](https://github.com/jampat000/Weir/issues).

This release candidate fixes how Weir answers a download your media manager sends twice, picks a file back up when it comes back, keeps an imported film from slipping back to "Waiting", and gives Weir's icon a thin inset border like Deluno's. It is also the first Weir release proven by the automated scenario run on a clean machine before it was tagged. Release candidate 14 was never published, because that scenario run found problems in the run itself; everything in it is here.

## What Changed

- **A download sent twice gets the right answer.** When your media manager sends the same download again, the new send takes over Weir's work and is told the result with the cleaned file; the earlier send is told it was replaced. Notes no longer mix, so a film never reads "imported" and "will not import" at once. Answers go only to the connection that sent the download. Addresses #955, #956.
- **A file that comes back is picked up again.** A file Weir saw as gone is looked at again as soon as it is back, instead of waiting ten minutes, and its hand-off is answered. Addresses #956.
- **An imported film stays imported.** A film your media manager imported no longer slips back to "Waiting for your media manager" after its download is cleaned up or handed over again.
- **Two connections sharing a download folder.** A file Weir is already working on for one connection is not taken for another; that connection is told Weir is busy and sends it again later.
- **A new logo border.** The Weir app icon, tray icon, browser icon and docs icon now carry a thin teal border set in from the rounded edge, like Deluno's, and the mark is a little smaller so it clears the border. Addresses #958.

## Fixes And Stability

- **Every release is proven before it is tagged.** A scenario run on a clean machine — install, update, first visit, real hand-offs from Deluno, pause, Process again, a deleted file and Logs — must pass on the exact commit before any release, release candidates included, can be published. Addresses #954.
- **The scenario run is now done in three steps around Deluno's suite.** First the build is installed over the Weir that Deluno's own installer put there, before Deluno sends any film; then, once Deluno's suite has made its hand-offs, the Deluno scenarios run; then the clean-machine scenarios run on a restored clean checkpoint. Each Deluno hand-off is judged by the Weir that handled it, so a hand-off the previous release answered is counted but never held against the new build. The checks for the update, resent hand-offs, small extras and Deluno's outcome records were corrected against what the first run showed, and a step that goes wrong no longer stops the next one.
- **The Docker start-up check no longer ends without a result.** When the container's health address hung, the check could end with no retry and no container log. A hung attempt now counts as a failed attempt, the check tries again, and the container's log is printed if every attempt fails.
- Two tests that measured time against the real clock now use their own clock, so a busy machine no longer fails them; Weir's real time limits were confirmed safe.
- The copyright line now reads "Copyright (C) 2026 jampat000 and the Weir contributors".

## Upgrade Notes

- Windows: **Check now** then **Download update** then **Restart and apply** in System › About, or install `Weir-win-Setup.exe` over the top. Before installing, Weir saves a copy of its data. Two database updates run on first start.
- Docker: change the image to `ghcr.io/jampat000/weir:1.0.0-rc.15`, then `docker compose pull && docker compose up -d`.

# Weir v1.0.0-rc.20

Date: 2026-10-22

> **Early days.** Weir is early, and it is in active, hard testing. Expect rough edges. If something is wrong or confusing, please report it on [GitHub issues](https://github.com/EJM-Digital/Weir/issues).

This release fixes two faults in the update path and a set of wrong or unclear messages that a much larger round of testing turned up. Nothing in it needs anything from you.

## Fixed

Updating:

- **A manual update check shows its answer while automatic checking is off.** On System › About, **Check for updates** now shows what it found (a newer version, or that you are up to date) even when Weir is not set to check by itself. Before, the answer was found and then not shown.
- **A busy computer no longer makes an update give up on its safety copy.** Before installing, the tray asks Weir to save a copy of its data. If the computer was busy and Weir was slow to answer, the update could fail at that step. The tray now waits for Weir to be ready and then carries on.

Wording and small faults:

- **Confirmation messages are in plain words.** Sign-in, media manager connections, account changes, pause and a few other places said "Invalid or expired CSRF token". They now say "Your confirmation token expired. Refresh the page and try again."
- **A file that disappeared while Weir read it no longer shows a folder path.** The message now asks you to check that the file is still in the watched folder and try again.
- **A manual pass on a workflow with no watched folder says what is missing.** It named an internal job instead of the workflow and the setting to fill in.
- **Exporting settings with a part missing explains it.** The message used to show the name of an internal table.
- **A detection window can be saved as it was read.** A workflow's detection window came back without a time zone and was then refused when saved, and a window given with an offset such as +02:00 was stored two hours out. Windows now keep the right time.
- **Activity reads correctly.** A pass that failed could read as done. An import by a manager that did not name itself read "Imported by Your media manager". A clean of one track read "1 tracks would come out". A file Weir had not started because it was busy with it for another connection no longer claims a newer send has the answer.
- **A library clean that is refused shows the reason.** Instead of a browser error, the page now shows what Weir said. A file whose track details cannot be read no longer stops the clean with a technical error: Activity says Weir could not make sense of the track details.
- **A restored time keeps its time.** A saved time with an offset other than UTC was shifted by that offset when a backup was restored.
- **Session check.** An account whose role Weir does not know is now refused when the page asks who is signed in, as it is everywhere else.
- **Network paths.** A share address with no share name is joined correctly in a hand-off report.
- **The tray log is clearer.** An update with no version number is no longer called "vunknown". If File Explorer cannot be started for a file, the tray opens the data folder as intended. The icon redraws if a blinking tick finds Weir has started.

## Under The Hood

- **Tests.** Several thousand more tests across the server, the web app and the tray, with coverage floors raised, replies recorded from the metadata service, and mutation testing of the risky core with a score that only goes up.
- **CI.** Heavy jobs run on main, nightly and before a tag. The Windows file, volume and share checks run on a hosted runner, and the scenario fixes found by the rc.19 clean-machine run are in. Every Weir image is now published under the organisation's name.

## Upgrade Notes

- Windows: **Check now** then **Download update** then **Restart and apply** in System › About, or install `Weir-win-Setup.exe` over the top. Before installing, Weir saves a copy of its data.
- Docker: change the image to `ghcr.io/ejm-digital/weir:1.0.0-rc.20`, then `docker compose pull && docker compose up -d`.

## Docker

- `ghcr.io/ejm-digital/weir:1.0.0-rc.20`
- Images are published for `linux/amd64` and `linux/arm64`, and run the .NET build of the Weir server.
